# Магазин одежды

Бэкенд курсового проекта на C#, ASP.NET Core Web API, EF Core и PostgreSQL.
API предназначен для клиента React.

## Локальный запуск

Понадобятся SDK .NET 10 и PostgreSQL 16. Для локальной проверки PostgreSQL можно запустить в Docker.

```sh
docker run --rm -d --name clothing-db \
  -e POSTGRES_DB=clothing_store \
  -e POSTGRES_USER=clothing_store \
  -e POSTGRES_PASSWORD=clothing_local \
  -p 127.0.0.1:5432:5432 postgres:16
docker exec clothing-db pg_isready -U clothing_store -d clothing_store
```

Когда `pg_isready` покажет, что БД принимает соединения, примените миграции и создайте первого администратора. Пароли ниже предназначены для локального примера.

```sh
export ASPNETCORE_ENVIRONMENT=Development
export ASPNETCORE_URLS=http://127.0.0.1:5000
export ConnectionStrings__Store='Host=127.0.0.1;Database=clothing_store;Username=clothing_store;Password=clothing_local'
export Bootstrap__AdminEmail='admin@example.test'
export Bootstrap__AdminPassword='LocalAdmin123'

dotnet run --project src/ClothingStore.Api -- --migrate --create-admin
dotnet run --project src/ClothingStore.Api
```

Для следующих развёртываний используйте `--migrate`; приложение при обычном запуске миграции не применяет. Контракт API в режиме Development доступен по адресу
[`/openapi/v1.json`](http://127.0.0.1:5000/openapi/v1.json).

## Сценарии API

| Маршрут | Назначение |
|---|---|
| `/api/auth` | Регистрация покупателя, вход, выход, профиль и контакты |
| `/api/catalog` | Каталог, поиск, фильтры, варианты и точки наличия |
| `/api/cart` | Корзина покупателя и изменение количества |
| `/api/orders` | Оформление, просмотр собственных заказов и отмена |
| `/api/management/catalog` | Ассортимент и справочники |
| `/api/management/orders` | Список заказов, подтверждение, подготовка, передача, завершение |
| `/api/management/inventory` | Точки учёта, остатки, поступления, перемещения и журнал |
| `/api/management/reports/sales` | Сводка продаж за период, при необходимости по одной точке |
| `/api/admin` | Доступ учётных записей и сравнение продаж по точкам |

Покупатель регистрируется через API. Чтобы завести менеджера, зарегистрируйте отдельную учётную запись, затем от имени администратора отправьте `PUT /api/admin/accounts/{id}/access` с телом `{"role":"manager","disabled":false}`.

Для React используйте один origin с API или проксируйте `/api` в режиме разработки.
Перед запросами `POST`, `PUT` и `DELETE` получите токен через `GET /api/auth/csrf`,
передавайте его в `X-CSRF-TOKEN` и отправляйте cookies. Получайте новый токен после входа или выхода.
Для `POST /api/orders/checkout` также передавайте UUID в `Idempotency-Key`. Повтор запроса с тем же ключом возвращает уже оформленный заказ. Для нового оформления создавайте новый ключ.
Отчёты принимают параметры `from` и `to` в ISO 8601 с часовым поясом. Конец периода не включается.

## Правила учёта

- Для самовывоза покупатель указывает магазин. Для доставки используется склад с наименьшим ID. Для демонстрации достаточно одного склада. Весь заказ комплектуется из одной точки.
- Сотрудники ведут операции по всем точкам. Сравнение точек доступно администратору.
- Размерная сетка закрепляется при создании модели. Позиции заказа хранят зафиксированные цену, название, артикул, размер и цвет.
- Оформление резервирует доступное количество. Отмена до передачи освобождает резерв. Завершение создаёт одну продажу, освобождает резерв и списывает товар.
- Исходная схема MySQL понадобится для переноса старых данных. Начальная миграция создаёт PostgreSQL-схему по модели курсового проекта.

## Проверка

```sh
dotnet build
python3 tests/api_smoke.py --url http://127.0.0.1:5000
```

Проверка использует только стандартную библиотеку Python, запускается с настроенным
администратором и создаёт записи через HTTP. Запускайте её на отдельной тестовой БД.
Сценарии включают роли, каталог, поступление и перемещение, атомарное оформление,
гонку за последнюю единицу, отмену, повторное завершение, доставку и отчётность.
